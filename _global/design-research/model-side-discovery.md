# Model-side discovery

## Problem
In design-research runs, the better option keeps turning up when the current options are presented to the user: the
out-of-the-box thinking is done by the user, not by the model, although finding those options is what the skill is
for. The research must find them itself, before the user sees the options.

## Related decisions
- Parent: `option-discovery.md` (decided 2026-10-24, "for now"): the leader is drafted and put through its real use
  each round, so the user sees the real shape earlier; the user still does the discovery legwork (its D10, known gap).
- Siblings: `requirement-reasons.md`, `skill-rule-following.md`, `skill-and-log-size.md` (all decided).

## Known so far
Cases where the user found the better option (P1-P3 and H1-H3 in `option-discovery.md`):
- challenging a rejection (H1, `skill-rule-following.md` round 7);
- changing the form of something (the options × requirements matrix; its orientation, `skill-and-log-size.md`);
- asking what something costs each time it is used (H2, H3).
Unresearched lead (2026-10-24): whether the model can make those moves on its own draft before the user sees it, for
example a check that receives the draft as the user would and is asked what it would change.
