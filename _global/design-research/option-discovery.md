# Option discovery

## Problem
The design-research skill must find the best option during the research, not leave it to the user's final review. In
the run on requirement reasons, the options × requirements matrix only came up at the Phase 6 review, though the
research had several hints to it.

## Related decisions
- Parent: `requirement-reasons.md` (decided). Sibling: `skill-rule-following.md` (open).

## Known so far
Hints the research missed (from `requirement-reasons.md`):
1. In round 2 the researcher built an error × option table to evaluate the options: the tool used to evaluate was
   itself the option.
2. QOC (found in round 1) is built around an options × criteria assessment; only its fields were taken, not its form.
3. The skill already required "score each option ... as a table", but the log template had no place for it; the
   "do nothing" option meant "leave the text as is", not "carry out what's already written".
Candidate additions to Phase 3's "always consider" list (not yet researched, offered 2026-10-24): the current
solution applied in full; found methods judged by their main artifact; the researcher's own evaluation tools as
options. The independent check was asked for missing options but given the log's framing.
